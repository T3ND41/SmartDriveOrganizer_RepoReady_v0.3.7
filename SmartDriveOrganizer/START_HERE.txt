SMART DRIVE ORGANIZER 0.3.6 — START HERE

WHAT IS NEW
Version 0.3.6 includes automatic background monitoring, user-defined partial keywords and exact destinations, plus paste-a-link GitHub publishing for shared rules and reviewed application source updates. Configure Downloads (and any other folders you want watched), set your topic rules and destinations, choose Copy or Move, and save. The monitor runs separately from the desktop window.

RUN THE DESKTOP APP
1. Extract the complete ZIP folder to a permanent location, for example C:\Tools\SmartDriveOrganizer.
2. Open that folder in File Explorer.
3. Click the address bar, type powershell, and press Enter.
4. Run: python run.py
5. The main window still includes manual Scan and preview, Apply organization, Undo last move and Undo last automatic move.

SELECTIVE TOPIC ORGANIZATION — YOUR OWN GROUPS
- In the main window or Automation Settings, enable selective topic organization.
- The built-in groups include Statements, Requisitions and Quotations.
- Click “Add / manage my own topic groups…” to create a folder label and enter your own keywords/phrases. Separate phrases with commas or new lines.
- Choose “Any” to match all enabled file types, or select one category such as Images or Videos.
- Select the group checkbox to activate it. Files matching selected groups go into Category\Topic\Extension folders; unselected and nonmatching files are left untouched.
- Example: folder label “Site Photographs”; phrases “site photo”, “worksite picture”, “inspection photograph”; category “Images”.
- For partial matching, enter a short code such as `QUO` and choose “Contains (partial keyword)”. It matches `Quotation - S01610.pdf`.
- Use “Browse…” to select a permanent destination for that topic. Matching files go directly into that folder, which is created automatically when needed and reused later. You may also type a new folder path. Leave the destination blank for the normal Category\Topic\Extension folder structure.
- Keyword mode and destination are saved with the topic and used by both manual organization and the background monitor. Edits are picked up by a running monitor on its next scan cycle.
- Filename matching works for all supported categories. Supported document text can also be searched when enabled. OCR, image recognition, video analysis and audio transcription are not included yet.

CONFIGURE AUTOMATIC MONITORING
1. In the main window, click Automation settings…
2. Under Folders to monitor, add Downloads. Add Desktop, Documents, or other folders where you save files too.
3. Choose the Organized Collection destination. This can be on another drive.
4. Select all file categories, or only the categories you want automatically organized.
5. Keep Copy files selected for the first test. Move is available after you are comfortable with the results.
6. Check Enable automatic monitoring now.
7. On Windows, optionally check Start the background monitor automatically when I sign in to Windows.
8. Click Save settings and start.

HOW IT WORKS
- The monitor checks the selected folders recursively every 5–60 seconds (10 seconds by default).
- It waits for a new file to become stable over several checks. On Windows it also checks that the file can be opened without another process holding it open.
- Temporary/incomplete download files such as .crdownload, .part, .tmp, .download and .partial are ignored. The final renamed file is detected.
- The output structure is Category\Topic\Extension\Filename. Existing topic and extension folders are reused; missing folders are created.
- Existing destination names are never overwritten. A numbered suffix such as (1) is added when necessary.
- Custom keyword rules saved from the main window are read by the background service on subsequent scan cycles.
- New files are automatically organized. Existing files are not all swept into the destination unexpectedly.

IMPORTANT FIRST-RUN BASELINE
The first time each monitored folder is activated, the application indexes the files already inside it and leaves them where they are. This prevents a newly enabled monitor from suddenly moving/copying an entire Downloads folder or drive. Use the manual Scan and preview screen to organize older files. Files arriving after the baseline are automatically processed. Files that arrive while the service is stopped are detected after it restarts, provided the monitored folder has already been baselined.

BACKGROUND SERVICE
- The background monitor is a separate process. Closing the desktop window does not stop it.
- Use Stop monitor in the desktop app to stop it. The desktop app also has **Undo last automatic move** for the latest automatic Move journal; it restores the original path when free and prevents immediate reprocessing.
- If Start with Windows is enabled, it starts when your Windows user account signs in. It is not a pre-login Windows service.
- Keep the extracted application folder in the same location after enabling startup. The startup entry refers to that folder's run.py file.
- On Windows, the startup setting is stored for the current user in HKCU\Software\Microsoft\Windows\CurrentVersion\Run. It does not require administrator privileges.
- The Activity log button opens the append-only automation activity log. Settings, state database, status and logs are stored under %LOCALAPPDATA%\SmartDriveOrganizer.

SAFETY
- Copy mode preserves the source file. Copies are SHA-256 verified before being published.
- Move mode relocates the file. Cross-volume moves are checksum-verified before the source file is removed as part of the move.
- No destination file is overwritten.
- Files in Windows/system/dependency directories, links/junctions, common temporary download formats, and detected software project subfolders are skipped.
- Files in categories you did not select are left in place.
- Unknown extensions are placed in Others when Others is selected.
- Automatic organization does not delete duplicate files. Identical files remain separate and are handled with unique names.
- The application does not request administrator access. Access-denied folders are skipped by the operating system and cannot be organized without permission.

PERFORMANCE
Monitoring a Downloads folder or a few work folders is recommended. Monitoring an entire drive requires recursively checking its folders on every polling cycle and can create noticeable disk activity. Use a longer interval for large monitored roots. Removable drives that are disconnected are skipped until available again.

GITHUB CONNECTION AND PUBLISHING (0.3.6)
1. Install Git for Windows or GitHub Desktop and sign in to GitHub once using Git Credential Manager / GitHub Desktop.
2. In the app, open Publish rules to GitHub…
3. Paste the main repository URL (for example https://github.com/YOUR-USERNAME/YOUR-REPOSITORY).
4. Click Save URL & connect. The app clones the repo into its own LocalAppData checkout and remembers the URL.
5. Publish keyword rules commits only config/published_topic_rules.json. Personal absolute destination paths are not shared.
6. Preview / publish app source update… shows changed program files before you approve a separate source-code commit. You can customize the commit message in the publisher window.
7. The source publisher only includes approved source, tests, launcher, manifests and documentation. It excludes personal settings, databases, logs and downloaded files.

Git authentication is handled by Git for Windows / GitHub Desktop / Git Credential Manager or GitHub CLI. Do not paste passwords or access tokens into the repository URL or app settings.
See PUBLISHING_TO_GITHUB.md for the full guide.


ONE-LINE INSTALLER DISTRIBUTION (0.3.6)
- Once the public GitHub repository and its first tagged Windows release exist, PowerShell can install the app without manually downloading the ZIP.
- Direct command: irm https://raw.githubusercontent.com/T3ND41/SmartDriveOrganizer/main/install.ps1 | iex
- Preferred short alias after domain configuration: irm https://smart.drive.win | iex
- The installer downloads the latest Windows release, verifies SHA256SUMS.txt, installs under %LOCALAPPDATA%\Programs\SmartDriveOrganizer, adds a Start Menu shortcut and launches the app.
- The release workflow builds the Windows EXE only on GitHub's Windows runner. No compiled EXE is included in this source archive.
- The custom smart.drive.win alias requires control of drive.win DNS plus deployment of cloudflare/worker.js. Until that is configured, use the GitHub Raw URL.
- irm | iex executes remote code. Inspect install.ps1 before running and only trust the repository endpoint.
